# Code Standards

## General

- Keep classes and methods small and single-purpose.
- Fix root causes; do not layer workarounds.
- Do not mix unrelated concerns in one class,
  component, or route.
- Prefer boring, explicit code over clever abstractions.
  No premature generalisation.
- Every behaviour change ships with tests.

## Java (API)

- Java LTS (version recorded in `architecture.md`).
  Build with the Maven Wrapper (`./mvnw`), never a
  globally installed Maven.
- Formatting by Spotless with google-java-format; run
  `make fmt` before committing. Compiler warnings are
  errors (`-Xlint:all -Werror`).
- **No Lombok.** Use records for DTOs and plain classes
  with explicit constructors and getters for entities,
  so the code shows exactly what it does.
- **Constructor injection only.** Dependencies are
  `private final` fields set in the constructor. No
  `@Autowired` on fields.
- Layering: controller → service → repository.
  Controllers map HTTP to one service call and return a
  DTO. Services hold business rules and transaction
  boundaries. SQL and JPA queries live in repositories,
  never in controllers. A feature may call another
  feature's service, never its repository.
- Controllers never return JPA entities. Map entities to
  response records with small static `from(...)` methods
  or a mapper class in the feature package (no MapStruct).
- Request DTOs are records with Bean Validation
  annotations (`@NotNull`, `@Positive`, `@Size`,
  `@Email`); controllers use `@Valid @RequestBody`.
- `@Transactional` goes on service methods, never on
  controllers. Read-only methods use
  `@Transactional(readOnly = true)`.
- Entities: `UUID` ids generated by the database;
  protected no-argument constructor for JPA; no public
  setters for ids or `workspace_id`. Reference other
  entities by their `UUID` id rather than
  `@ManyToOne` unless a join is genuinely needed, to
  avoid lazy-loading surprises.
- Money fields are `long` and named `*Paise`
  (`amountPaise`). Never `float`, `double`, or
  `BigDecimal` for stored amounts. Use `Math.addExact`
  and `Math.subtractExact` when summing.
- Time: `LocalDate` for calendar dates (`occurred_on`,
  `due_date`), `Instant` for timestamps, `ZoneId` for the
  user's timezone. Never `java.util.Date`. Get "now" from
  an injected `Clock` bean so tests can control time.
- Enums for fixed value sets (`TransactionType`,
  `DueDirection`), stored as lowercase strings matching
  the database check constraints.
- `Optional` only as a return type for "might not
  exist"; never as a field or parameter. Public methods
  do not return `null`.
- Services throw domain exceptions (`NotFoundException`,
  `ConflictException`, `ValidationException`,
  `ForbiddenException`) from `common/web`; one
  `@RestControllerAdvice` maps them, plus validation and
  JSON parse errors, to the error shape below.
- Logging with SLF4J. Never log passwords, tokens,
  cookies, or full request bodies.
- Add a short comment wherever Spring does something
  non-obvious (an annotation that changes behaviour, a
  security filter, transaction propagation), so the code
  is readable by someone new to Spring.

## TypeScript (Web)

- Strict mode throughout. No `any`; use the generated
  API types from `lib/api/schema.d.ts` or narrow types.
- Never hand-edit `lib/api/schema.d.ts`; regenerate it
  with `make gen-api` after API changes.
- Validate form input with Zod before sending it.
- Validate unknown external input at boundaries before
  trusting it.
- Money arrives from the API as integer paise. Convert
  user input only with `rupeesToPaise` and display only
  with `formatINR` / `formatINRCompact`.

## Next.js

- App Router. Default to server components for layout
  and static content; add `"use client"` only where
  browser interactivity requires it.
- Browser data fetching goes through TanStack Query
  hooks in `lib/queries/`, one hook per resource action.
- Always call relative `/api/v1/...` paths (proxied by
  the rewrite). Never call the API origin directly.
- Keep pages thin; compose feature components.

## Styling

- Use the CSS custom property tokens from
  `ui-context.md` through the Tailwind theme mapping. No
  hardcoded hex values.
- Follow the border radius scale and layout patterns in
  `ui-context.md`.
- Desktop-first design, responsive code: design and
  verify every screen at 1280px first, then confirm it
  works without horizontal overflow at 360px. Tailwind
  breakpoints are min-width, so base classes describe
  the narrow layout and `md:`/`lg:` classes the desktop
  one.

## API Routes

- Base path `/api/v1`. Workspace-scoped resources live
  under `/api/v1/workspaces/{workspaceId}/...`.
- JSON field names are snake_case (`amount_paise`,
  `occurred_on`), configured once globally in Jackson;
  Java code stays camelCase.
- Validate and parse input before any logic runs.
- Authentication is enforced by Spring Security.
  Workspace membership is checked by
  `WorkspaceAccess.require(workspaceId, role)` at the
  start of every workspace-scoped service method;
  non-members get 404.
- Consistent success responses: the resource object, or
  `{ "items": [...], "next_cursor": "..." | null }` for
  lists.
- Consistent error shape:
  `{ "error": { "code": "snake_case_code", "message": "Human readable", "details": {...} | null } }`.
- Cursor pagination for growing lists, ordered by
  `occurred_on DESC, created_at DESC, id DESC` (newest
  entered first within a day; the random id is only the
  final tie-break); default page size 50, maximum 200.
- Dates as ISO strings (`YYYY-MM-DD` for dates, ISO 8601
  UTC for timestamps). Money as integer paise.
- Response DTOs mark every field that is never null with
  `@NotNull` (see `MeResponse`, `TransactionResponse`).
  springdoc turns that into `required`, so the generated web
  types have no `?` on those fields and the web code needs no
  `!`. Nullable fields (a note, a category) stay unmarked and
  arrive as `null`, not as a missing key.
- `PATCH` for partial updates where "left out" can mean
  "keep" (accounts, categories). `PUT` for resources an
  edit form always sends in full (transactions): the body
  replaces everything, so optional fields left out are
  cleared. `DELETE` soft-deletes
  where the model supports it, with
  `POST .../{id}/restore` to undo.

## Data and Storage

- Structured data and metadata belong in Postgres.
  Files belong in R2.
- Do not store files or large blobs in the database.
- All object storage goes through `ObjectStorage`; no other
  class builds an S3 client. Stream file bodies
  (`InputStream` plus a known length); never read a whole
  upload into memory. Upload as the raw request body with
  the file's own `Content-Type`, not multipart, so the CSRF
  reasoning in `SecurityConfig` holds. Never put a
  user-supplied file name in an object key or an HTTP header
  unencoded (use `ContentDisposition`).
- Serve user files with `X-Content-Type-Options: nosniff`
  and `Content-Security-Policy: sandbox`.
- When a database row and a stored file change together,
  write the row first and the file second on create, and
  delete the file only after the row's deletion commits
  (`TransactionSynchronization.afterCommit`).
- Tests use real storage too: `PostgresTestBase` starts an
  s3mock container next to Postgres.
- Every schema change is a new Flyway migration
  (`V<n>__<description>.sql`). Check each one for: RLS
  enabled and forced on new workspace-scoped tables,
  policies, grants to `hisaab_app`, and indexes on
  `workspace_id` and common filter columns.
- Hibernate never creates or alters tables
  (`ddl-auto: validate`).
- Enforce invariants with database constraints where
  possible (`CHECK (amount_paise > 0)`, unique
  constraints for idempotency, foreign keys).

## Testing

- JUnit 5 + AssertJ. API tests run against real
  Postgres through Testcontainers (with the same role
  setup script as local Docker), never H2, because RLS
  and constraints are part of the behaviour.
- Endpoint tests use `@SpringBootTest` with MockMvc.
  Pure logic (period maths, outstanding amounts) gets
  plain unit tests without Spring.
- Every workspace-scoped endpoint has a happy-path test,
  a validation test, and a cross-workspace access test.
- Money and period calculations have edge-case tests:
  month boundaries, period start days in 28–31-day
  months, leap years, zero and very large amounts.
- Test names describe behaviour:
  `nonMemberGets404WhenListingTransactions()`.
- Web: Vitest unit tests for formatting and money
  conversion helpers.

## File Organization

- `apps/api/pom.xml` — dependencies and build plugins
- `apps/api/src/main/java/in/hisaab/HisaabApplication.java`
  — entry point
- `apps/api/src/main/java/in/hisaab/<feature>/` —
  controller, service, repository, entity, and `dto/`
  for one feature
- `apps/api/src/main/java/in/hisaab/common/` — shared
  web, security, db (RLS), money, and config code
- `apps/api/src/main/java/in/hisaab/jobs/` — job queue
  and poller
- `apps/api/src/main/resources/application.yml` —
  configuration and profiles
- `apps/api/src/main/resources/db/migration/` — Flyway
  migrations
- `apps/api/src/test/java/in/hisaab/` — tests mirroring
  the main packages
- `apps/web/app/` — routes and layouts
- `apps/web/components/ui/` — shadcn components (generated)
- `apps/web/components/<feature>/` — feature components
- `apps/web/lib/` — API client, generated types, query
  hooks, formatting helpers
